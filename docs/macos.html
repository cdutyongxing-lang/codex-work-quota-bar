Codex Work 额度条

在 macOS 菜单栏同时查看 5 小时与每周剩余额度。

没有普通主窗口是正常现象。打开应用后，请查看屏幕顶部菜单栏中的圆环图标和额度数字。菜单栏模式不需要辅助功能权限。

开始使用

  1. 把 CodexQuotaBar.app 放入“应用程序”并双击打开。
  2. 打开已登录的 ChatGPT / Codex 主应用，等待几秒。
  3. 菜单栏显示类似 5h 80% · 周 65% 的读数；数字为示例，实际显示取决于账户返回。

额度与刷新

v1.1.1 低额度保护：在菜单“Codex 低额度保护（15%）”中启用，可预设或自定义 1–90% 阈值。首次从子菜单打开 Hook 审查终端，输入 /hooks，审查并信任包含 quota-hook 的 PostToolUse 条目；完成后重开主应用和会话。

默认关闭。只有已加载该 Hook 的本机 Codex，才会在下次工具调用完成后收到保存进度与结束本轮的提示。同一本机工具共享的每个 5 小时周期，所有会话合计最多一次；你后续明确要求继续即可继续，不唤醒空闲聊天，不强制中断，不控制云端 Work。“最近生成提示”不能证明已保存。模型收尾会使用额度；暂停、关闭保护或退出工具会停用提示。完整步骤见应用内资源中的 QUOTA_GUARD.md。

百分比均表示剩余。约每 60 秒读取一次额度，不发送提示词或创建模型任务。查询本身不应消耗模型额度；正常执行任务仍会使用额度。主应用在后台时仍会查询。

点击菜单查看重置倒计时，悬停可查看北京时间重置日期和最近读取时间。“暂停自动刷新”停止后续自动查询并隐藏悬浮条，菜单栏会标记“已暂停”；已发出的请求可能完成。“立即刷新一次”在暂停时也可使用，读取后仍保持暂停。“恢复自动刷新”会立即尝试读取。“退出额度条”结束程序。

主应用退出后，旧数据标记“待更新”；重新打开后重新连接。若主动暂停过，重新打开主应用后仍会保持暂停。完全退出并重开额度条后，自动刷新默认开启。v1.0.2 修复了旧版暂停时手动刷新失效的问题；更新前请先退出旧版。

可选：跟随窗口

  1. 勾选“跟随 ChatGPT 窗口（需辅助功能）”。
  2. 自行在系统设置中决定是否授予辅助功能权限。
  3. 切回主应用。若无法定位，使用“手动校准位置”，拖到空白处，再右键选择“完成校准”。

跟随默认关闭。辅助功能权限范围比窗口定位用途广，仅在信任此构建时授予。布局变化可能导致定位失败，菜单栏仍可使用。

找不到 CLI 或没有额度？

先点击菜单检查状态，确认主应用已打开、网络正常、CLI 与桌面应用登录同一 ChatGPT 账户。菜单可手动“选择 Codex CLI…”。新版内置 CLI 常见相对路径为 Contents/Resources/codex-cli/CodexCLI.app/Contents/MacOS/codex。部分账户或 API Key 登录模式可能没有此类数据。

工具不直接读取登录令牌，不要向他人提交密码、Cookie、API Key 或 auth.json。失败时保留旧值并标记待更新，不将缺失数据视为满额。

签名、更新与移除

本应用使用 ad-hoc 签名，尚无 Apple Developer ID 签名或公证。遇到系统拦截时，先核对来源，再参照 Apple 官方说明决定是否打开。无需关闭全系统安全保护。

更新前先退出旧版，再替换应用。登录启动需要主动开启；启用前先将应用放到稳定位置。移除前关闭登录启动并退出，再删除应用。无需删除 Codex 登录文件。
