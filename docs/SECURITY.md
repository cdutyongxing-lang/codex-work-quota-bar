# 安全与隐私

## 数据流

```text
菜单栏工具 → 本机官方 Codex CLI（app-server / stdio）→ 额度服务
```

工具层仅调用 `initialize`、`initialized` 和 `account/rateLimits/read`，不创建对话或模型任务，不消费额度重置奖励，也不调用邮件发送接口。

网络请求、登录凭据读取与必要的凭据刷新由 CLI 处理。请使用可信的官方 CLI，保持 CLI 与桌面应用登录同一账户。手动选择的 CLI 路径和 PATH 候选未做开发者签名校验，不要指定不明文件。

## 权限

菜单栏模式不需要辅助功能权限。窗口跟随为可选功能，首次默认关闭。定位代码请求窗口 / 控件角色与几何，以及按钮标题和描述，不请求文本输入框的 AXValue。工具不申请屏幕录制权限。

辅助功能是范围较广的系统权限，程序未来若遭恶意修改，可能读取更多界面或执行操作。本应用也未启用 App Sandbox，不能把当前源码没有执行某操作理解为系统阻止其执行。

## 本地保存

工具将窗口跟随开关、校准位置、CLI 路径和额度类型选择存入 macOS 用户偏好。额度快照保存在内存中；不将 CLI 标准输出、错误输出、聊天正文或登录令牌写入文件。

工具源码没有独立的遥测与数据上传逻辑。官方 CLI 的诊断、网络及遥测行为由其自身版本和配置决定。

## 签名与构建

发布应用使用 ad-hoc 签名，不含 Apple Developer ID 签名或公证。SHA256 只能检查下载文件是否与发布校验值一致，无法证明作者身份、程序安全或二进制必然对应源码。

需要更强的源码可追溯性时，可自行检查源码并构建。GitHub Actions 的运行记录也可辅助核对构建来源。

## 反馈问题

普通故障报告只需系统版本、应用版本、CLI 版本、工具版本及已脱敏的现象。不要提交 `.codex`、`auth.json`、API Key、Cookie、完整诊断文件或个人聊天截图。

如果发现可能泄露凭据的问题，请先通过仓库维护者提供的私密联系方式报告；没有私密渠道时，可先提交不包含敏感信息和利用细节的联系请求。维护者尚未配置安全报告渠道时，本项目不宣称已有私密漏洞提交入口。
