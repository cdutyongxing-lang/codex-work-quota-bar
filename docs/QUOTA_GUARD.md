# Codex 低额度保护（v1.1.1）

默认阈值为 **5 小时剩余 15%**，可在菜单中改为预设值或自定义 1–90 的整数。该功能需主动启用，不会仅因打开额度条就修改 Codex Hook 配置。

## 首次启用

1. 先从旧版额度条菜单选择“退出额度条”，再打开新版。
2. 点击菜单栏额度 →“Codex 低额度保护（15%）”→ 勾选“启用低额度提示”。
3. 工具将保护程序复制到用户 Application Support 目录，并将自己的 `PostToolUse` Hook 合并到 Codex 用户 `hooks.json`；已有 Hook 保留，变更前备份。
4. 在同一子菜单点击“打开 Codex Hook 审查终端…”。它会打开一个空目录中的 Codex CLI，不自动提交模型提示词。
5. 在 CLI 中输入 `/hooks`，审查并信任包含 `quota-hook` 的 `PostToolUse` 条目。Codex 要求对非受管 Hook 进行一次审查；本工具不会代为信任、修改信任记录或使用绕过选项。
6. 退出审查终端，重新打开桌面主应用并启动新的本机 Codex 会话。已经启动且没有加载该 Hook 的会话不会被自动接管。
7. Codex 完成一次受支持的工具调用后，菜单应显示“最近已收到 Codex Hook 检查”。若仍显示等待，请检查 Hook 是否信任、运行时是否支持本机 Hook、是否重开会话。

只审查自己信任的本地程序。若 CLI 首次询问项目目录信任，本工具准备的是专用空目录 `hook-review`；无需为了本功能授予整个主目录信任。

## 触发方式

```text
每分钟读取 Codex 额度
        ↓
原子写入本地状态文件
        ↓
正在工作的 Codex 完成一次工具调用
        ↓
PostToolUse Hook 在本机检查最新状态
        ↓
5h 剩余 ≤ 阈值时，向当前任务返回保存进度和收尾提示
```

这不是向聊天界面模拟键盘输入，也不会创建或唤醒空闲聊天。连续推理或长时间工具调用期间无法立即打断，需等下一个受支持的工具调用完成。

提示要求：在最近的安全节点停止新增工作，保存已有修改，在项目进度文件或 `CHECKPOINT.md` 中记录完成情况、剩余事项、修改文件、测试结果及恢复步骤，然后结束本轮，等待用户下一条指示。它不自动推送、部署、删除、强制结束外部任务，也不让模型循环等待额度重置。

升级无法撤回已经进入会话历史的旧版提示。如果旧会话仍沿用旧要求，可明确告诉它：“继续工作，本周期已经完成低额度保存，不要因之前的额度提示再次暂停；后续由我决定是否继续。”

这是给 AI 的提示，不是硬性暂停机制。工具记录“最近生成提示”，不能据此认定模型已收到、已完成保存或已停止；请以任务回复及实际进度文件为准。

## 去重与开关

- 同一本机工具共享的每个实际 5 小时周期，所有会话合计最多生成一次提示。第一个达到条件的活动会话收到提醒后，其他会话也不会在这个周期再次收到提醒。
- 提示只要求触发时这一轮保存并结束。你之后明确发送“继续”或新的工作指令时，由你决定继续，不必等额度恢复。
- 重启、关闭再开启保护、调整阈值及新建会话都不会清除本周期记录。升级时继承 v1.1.0 已有回执；不要手动删除回执来更新。
- 同周期的重置时间数值修正不会重新触发；只有记录的重置时间已到，并读取到新周期的有效快照后，才重新允许一次提醒。
- 暂停自动刷新、关闭保护、主应用退出或正常退出额度条，都会写入停用状态。
- 如额度条异常退出，超过 180 秒的旧快照不会触发；缺失额度、缺少有效重置时间、窗口已过期或输入异常时均不提示。
- 并发检查通过文件锁与持久回执去重；回执损坏时不自动重置，避免重复提示。
- “移除本工具的 Hook 接入”只移除本工具的定义并保留其他 Hook；辅助程序和本地回执可留作恢复，不再被本工具 Hook 调用。Codex 可能需要重开会话才能更新 Hook 定义。

## 支持范围

面向支持并信任 `PostToolUse` Hook 的本机 Codex 运行时。本机验证 CLI 为 `0.164.0-alpha.11.1`，其 `hooks` 功能已启用；不同版本及桌面运行方式仍需验证。

本功能不承诺控制云端 ChatGPT Work、普通 ChatGPT 聊天、远程主机的 Codex，或没有加载用户 Hook 的会话。使用自定义 `CODEX_HOME` 时，额度条与目标 Codex 必须使用同一配置目录。默认读取 `~/.codex/hooks.json`。

当前仅监测 `codex` 额度桶的 300 分钟窗口，不将周额度、其他模型桶或缺失数据当作 5 小时额度。周额度可能先耗尽，不能因为本功能没有触发就认为所有额度都足够。

## 额度与本地数据

额度查询、本地比较与空结果 Hook 检查不创建模型任务。触发后模型理解提示、整理和保存进度仍会消耗模型额度；不能承诺固定开销或一定能在剩余额度内完成。每分钟采样也可能滞后于快速消耗，建议按任务规模留足余量。

本地状态保存在用户 `Library/Application Support/CodexQuotaBar/`：

- `quota-state.json`：开关、阈值、读取时间、5 小时剩余与重置时间。
- `quota-hook`：本工具自身可执行文件的副本，以 `--quota-hook` 模式运行，不打开界面或联网。
- `hook-receipts.json`：会话 ID 的 SHA256 摘要、窗口标识和检查 / 提示时间。
- `hook.lock`：并发锁。
- `review-hooks.command` 与 `hook-review/`：可选审查终端启动器及空目录。

Hook 不保存聊天或工具结果。Codex 会把事件传入 Hook，程序只使用事件类型及会话标识；超大或无效输入会静默跳过。状态资料目录权限为用户独占，状态及回执文件设为仅用户读写。正常路径不直接读取账号凭据。

所有自动检查在临时目录与模拟事件中运行，不向真实任务发送指令。v1.1.0 已由用户在 CLI 实测接收提示、写入进度并结束回合；v1.1.1 的周期去重和提示范围通过 97 项本地检查，实际任务行为仍需确认。菜单中的“本周期已提醒”表示已生成提示，不代表模型已保存。

依据：[官方 Hooks 文档](https://learn.chatgpt.com/docs/hooks)。
